## What's locked — do not relitigate

**From Phase 0 (PR #226):**
- `minion-gateway` translator daemon, not per-daemon gRPC. Forced by the bidirectional reading of `project_minion_mandatory` (ServiceDaemons never accept inbound network connections).
- Hard cut to gRPC at v1.2.0 GA boundary; `MINION_TRANSPORT=kafka` is rc1 emergency rollback only.
- No Minion-side buffer; gRPC `ManagedChannel` reconnect-with-backoff handles transient outages.
- Envoy ingress, not Spring Cloud Gateway.
- Heartbeat first; other sinks have `.proto` definitions but no implementations in rc1.

**From the implementation plan (PR #228):**
- Spring gRPC 1.0.3 (`org.springframework.grpc:spring-grpc-spring-boot-starter`); BOM ordering: `spring-boot-dependencies:4.0.3` first, `spring-grpc-dependencies:1.0.3` second.
- Bidi-streaming `HeartbeatService.Publish(stream Heartbeat) returns (stream HeartbeatAck)` — long-lived per-channel stream, ack per message.
- Identity in gRPC metadata (`x-minion-id`, `x-minion-location`), payload identity is duplicate-for-logging only; metadata is authoritative for `minion-gateway` Kafka routing.
- Single-line cutover via `@Qualifier("heartbeatDispatcherFactory")` on `HeartbeatConfiguration`'s `MessageDispatcherFactory` parameter. No other listener config changes.
- `GrpcMessageDispatcherFactory.createSyncDispatcher()` throws `UnsupportedOperationException` for any module-id other than `"Heartbeat"` — fail-fast on misrouting.
- h2c plaintext within compose; TLS termination at Envoy is a pre-GA add when remote-Minion deployments are validated.
- Reuse `core/horizon-metric-bridge` (PR #216, 2026-04-24); don't reimplement. Wire `new HorizonMetricsBridge(metricRegistry, "opennms")` per the syslogd pattern.
- Java 21 reactor (per CLAUDE.md fix PR #229).

If something feels wrong about any of these, **surface to the user explicitly before changing course.** The plan was reviewed and approved 2026-04-26.
